# ArchDeck 글로벌 서비스 벤치마킹과 제품 방향

검토 기준일: 2026-11-27 · 대상: 초기 제품 기획과 MVP 범위

ArchDeck은 엔지니어가 기술 개념을 이해하고, 아키텍처 대안을 비교하고, 실무 점검까지 이어갈 수 있는 학습·판단 도구로 기획한다. 벤치마킹 우선 3개는 **ByteByteGo, roadmap.sh, Refactoring.Guru**로 선정했다. 이는 시장 점유율이나 매출 순위가 아니라 ArchDeck의 목적에 대한 제품 적합성 판단이다.

## 선정 기준

1. 아키텍처와 기술 개념을 그림·구조로 설명하는가.
2. 한 개념을 이해한 뒤 다음 행동과 학습 순서를 안내하는가.
3. 적용 조건·대안·장단점을 일관되게 설명하는가.
4. 단순 사내 계정으로 열람하는 학습 도구에 도입할 수 있는 패턴이 있는가.
5. 현재 React·TypeScript·Spring Boot 구조에서 MVP로 구현할 수 있는가.

공식 공개 페이지의 현재 기능을 확인했다. 아래의 ‘적용’은 ArchDeck을 위한 제품 제안이며, 해당 서비스가 동일 기능을 제공한다는 의미가 아니다.

| 선정 서비스 | 공식 공개 페이지에서 확인한 특성 | 선정 이유 | ArchDeck에 적용할 패턴 | 도입하지 않을 패턴 |
|---|---|---|---|---|
| ByteByteGo | 텍스트 강의에 상세한 그림을 결합해 단계별 설명을 제공하고 공개 미리보기와 Visual Guides를 운영한다. | 시스템 구성의 전체 그림과 설명을 함께 전달하는 데 적합하다. | 토픽별 전체 구성도, 단계 선택 시 설명·요청 예제 동시 강조, 핵심 차이를 압축한 요약 | 인터뷰 합격 중심 메시지, 구독·결제 흐름, 긴 판매용 랜딩 화면 |
| roadmap.sh | 역할·기술별 로드맵, 클릭해 학습 자료로 이동하는 인터랙션, 진행 상태 추적, 기여·검토 절차를 소개한다. | ‘무엇을 다음에 배워야 하는가’를 구조로 보여준다. | 선행·후속 주제 연결, 홈의 이어서 학습, 토픽별 이해 완료 상태, 권장 학습 순서 | 공개 프로필, 순위, 계정 기반 동기화, 초기 단계의 대형 로드맵 편집기 |
| Refactoring.Guru | 패턴 카탈로그와 개별 문서에 문제·해결·구조·적용 조건·구현 순서·장단점·관련 패턴을 일관되게 제공한다. | 콘텐츠가 늘어나도 상세 화면의 품질과 탐색 방식을 유지하기 좋다. | 모든 토픽의 공통 상세 템플릿, 적용 조건과 피해야 할 조건, 연관 비교·용어·체크리스트 연결 | 패턴 분류를 ArchDeck의 최상위 메뉴로 그대로 복사하거나 객체지향 패턴 중심으로 범위를 제한하는 방식 |

|---|---|---|

| AWS Well-Architected | 프레임워크·렌즈·평가 도구를 연결하고 워크로드 위험과 개선 사항을 기록하는 방식을 제공한다. [공식 소개](https://aws.amazon.com/architecture/well-architected/) | 실무 체크리스트의 보조 참고로 유용하다. 다만 AWS 워크로드 평가라는 범위가 ArchDeck의 범용 기술 학습보다 좁다. |

AWS를 체크리스트 품질의 보조 참고로 삼아 각 항목을 **점검 질문 → 적용 조건 → 검증 방법 → 근거 → 기록**으로 구성한다. 학습자가 체크했다는 사실과 실제 시스템이 안전하다는 판정은 구분한다. 자동으로 보안 인증이나 규제 준수를 보장하는 문구를 사용하지 않는다.

## 제품 정의

**대상 사용자:** 인증·보안·시스템 구성 원리를 배우거나 설계 대안을 비교하는 프론트엔드·백엔드 엔지니어, 기술 리드, 아키텍트.

**사용자가 해결할 질문:** “이 기술은 왜 필요한가”, “어떤 구성으로 동작하는가”, “대안 중 어떤 것이 우리 조건에 맞는가”, “적용 전에 무엇을 확인해야 하는가”.

**제품의 중심 행동:** 토픽을 읽는 것에서 끝나지 않고, 단계 흐름을 확인하고 대안을 비교한 뒤 점검 결과와 개인 메모를 남긴다.

**제품 약속:** 같은 토픽에서 개념·흐름·비교·용어·검증 근거를 연결해 제공한다. 검색 결과는 관련 메뉴가 아니라 선택한 상세 항목으로 이동한다.

## 운영과 개인 기록의 경계

사용 환경은 **자기 PC에서 콘텐츠를 작성·관리하고 사내 여러 사람이 로그인해 읽는 공유 서비스**다. 최신 요구에 따라 아이디·비밀번호 로그인과 헤더 로그인 진입을 포함한다. 단일 same-origin 서비스에서 서버가 ADMIN·READER 역할을 검사하며, ADMIN의 사내 HTTPS 관리 작업도 허용한다. 헤더는 로그인 전 로그인 버튼, 로그인 후 이름과 로그아웃을 제공한다. 알림 아이콘은 두지 않는다.

| 데이터·행동 | 보존 위치와 범위 |
|---|---|
| 게시된 토픽·비교·용어·체크리스트·안내 경로 | 게시자 PC의 호스트 DB에서 관리하고 로그인한 사내 사용자에게 공통 제공한다. 미인증 API·정적 번들에서 콘텐츠와 검색 메타데이터를 노출하지 않는다. |
| 콘텐츠 작성·수정·게시와 계정 관리 | ADMIN 역할에만 허용한다. READER는 게시 콘텐츠를 조회한다. 공개 회원가입은 제공하지 않는다. |
| 개인 북마크·진도·메모·최근 열람·점검 기록·외관 설정 | 각 브라우저에서 안정적인 서비스 인스턴스 식별자 `serviceId` + 불변 사용자 UUID `userId`별로 나누어 저장한다. 로그아웃 시 화면·메모리에서 내리고 서버의 공용 사용자 한 건으로 합치지 않는다. |
| 다른 기기로 개인 기록 이동 | JSON 백업·복원을 제공한다. 계정 기반 자동 동기화는 현재 범위에 포함하지 않는다. |

추천 순서와 다음 학습은 첫 데이터 모델의 `learning_paths`와 `learning_path_items`로 표현한다. 별도 경로 편집기나 대형 그래프가 없어도 홈과 상세 화면에서 같은 경로 데이터를 활용할 수 있다.

## 핵심 사용자 여정

| 단계 | 사용자 행동 | 제품의 지원 | 완료 상태 |
|---|---|---|---|
| 탐색 | 목적이나 키워드로 주제를 찾는다. | 통합 검색, 카테고리·태그 필터, 최근 열람과 추천 순서 | 선택한 토픽의 상세가 열린다. |
| 이해 | 전체 구성을 본 뒤 단계별 동작을 확인한다. | 노드·연결선, 활성 단계, 요청·응답 예제, 용어 설명 | 동작 순서와 신뢰 경계를 설명할 수 있다. |
| 판단 | 다른 방식을 나란히 비교한다. | 같은 평가 차원, 적용 조건, 비용·위험·장단점 | 선택 기준과 선택하지 않은 이유를 기록할 수 있다. |
| 검증 | 적용 전 확인할 항목을 점검한다. | 우선순위, 검증 절차, 출처, 관련 예제 | 미점검·확인·해당 없음 상태와 근거를 구분한다. |
| 기록·재방문 | 북마크·이해 완료·메모를 남긴다. | 내 서재, 이어서 학습, 내보내기·가져오기 | 같은 브라우저에서 문맥을 이어갈 수 있다. |

‘이해 완료’와 체크리스트의 ‘확인’은 서로 다른 상태다. 토픽 학습 진도와 실무 점검 결과를 하나의 점수로 합치지 않는다.

## 공통 콘텐츠 템플릿

모든 토픽의 상세는 다음 순서를 기본으로 한다.

1. 해결하려는 문제와 전제 조건
2. 한눈에 보는 시스템 구성과 신뢰 경계
3. 단계별 요청·응답과 예외 흐름
4. 적용할 상황과 피해야 할 상황
5. 장단점과 대안 비교
6. 보안·운영 검증 항목
7. 관련 용어·선행/후속 주제
8. 원문 출처, 적용 제품·규격 버전, 마지막 검토일

흐름이 없는 개념 문서는 빈 배열을 오류로 취급하지 않고 구성도·단계 섹션을 생략할 수 있어야 한다. 단계가 필수인 아키텍처 토픽과 일반 개념 문서의 요구 필드를 스키마에서 구분한다.

## MVP와 후속 범위

| 범위 | 포함 항목 | 범위 기준 |
|---|---|---|
| MVP 안정화 | 기존 5개 토픽·3개 비교·10개 용어·9개 체크포인트의 FE/BE 대조, 누락 참조와 빈 흐름 처리, 일관된 스키마·저장 결과 | 기존 콘텐츠의 핵심 여정을 오류 없이 완주한다. 검토 중 누락된 체크 항목은 추가하거나 참조를 정정한다. |
| MVP 탐색·학습 | 토픽 상세, 단계 흐름, 비교, 용어, 체크리스트, 통합 검색과 다중 필터, 상세 URL, 선행·다음 학습 연결 | 메뉴를 늘리는 대신 상세 간 연결을 완성한다. |
| MVP 개인 도구 | 북마크·이해 완료·메모·최근 열람·점검 기록, JSON 백업·복원 | 브라우저 + `serviceId + userId`별로 보존한다. 다른 브라우저·기기 자동 동기화를 약속하지 않는다. |
| MVP 작성 도구 | 스키마 기반 콘텐츠 작성·수정·미리보기·JSON 내보내기, 참조 검증, ADMIN의 콘텐츠 관리 흐름 | 코드 수정 없이 새 콘텐츠를 추가할 수 있고 잘못된 구조는 게시 전에 검출한다. 조회·작성 권한은 서버에서 검사한다. |
| MVP 계정·접근 | 단순 아이디·비밀번호 로그인, ADMIN의 계정 생성·사용 중지·비밀번호 재설정, 최초 비밀번호 변경, 서버 세션 | 공개 회원가입·SSO·앱의 Keycloak 연동·JWT·Redis는 도입하지 않는다. 별도 프로필 제품과 알림은 추가하지 않는다. |
| MVP 외관 | DWP 스타일 공통 shell, preset, 좌·우·상단 메뉴, 사이드바 접기, 주간·야간·시스템, 밀도·대비·모션·초기화 | 기존 외관 요구를 유지하며 헤더의 로그인 상태와 설정 버튼을 독립적으로 제공한다. |
| P2 | 별도 학습 경로 화면, 퀴즈·시나리오형 확인 문제, 고급 비교 저장, 근거가 포함된 점검 보고서 | 핵심 학습 루프와 콘텐츠 품질이 검증된 뒤 확장한다. |
| 후속 검토 | 팀 협업·토론, 공개 기여 워크플로, 문서/Git 웹훅, 개인 기록 서버 동기화 | 단순 사내 로그인 도입을 협업 플랫폼 확대와 동일시하지 않는다. 별도 요구와 운영 정책이 필요하다. |

정식 버전 이력의 범위는 작성 흐름의 초안·게시·복구 요구와 함께 설계한다. ADMIN·READER의 기본 접근 제어는 MVP에 포함하고 다단계 승인·세분화된 팀 권한은 후속으로 둔다. 콘텐츠 자체의 버전·출처·검토일은 처음부터 보존한다.

## 제품 완료 기준

- 관리자가 발급한 계정으로 로그인한 사용자가 SPA와 BFF의 차이를 찾고, 단계 흐름과 비교를 연속해서 탐색할 수 있다.
- 비교와 체크리스트에서 판단 근거와 검증 방법을 확인할 수 있다.
- 새 콘텐츠가 검색·분류·상세·관련 항목에 같은 ID와 내용으로 반영된다.
- 토픽 완료, 점검 확인, 북마크, 메모가 독립적으로 보존되고 가져오기 후에도 연결이 유지된다.
- 서버 데이터가 비어 있거나 요청이 실패해도 빈 화면·저장 성공 오표시·원격 기록 덮어쓰기가 발생하지 않는다.
- 미로그인 요청은 콘텐츠·검색 메타데이터를 받지 못하고 READER는 관리 API를 실행하지 못한다. 로그아웃·사용 중지·비밀번호 변경 후 기존 세션의 재사용이 차단된다.
- 위 여정을 데스크톱·모바일·키보드에서 검증한다. 로그인 수·커뮤니티 규모나 수강자 순위를 학습 성과 지표로 삼지 않는다.

## 벤치마킹 자산 사용 원칙

벤치마킹 대상의 정보 구조와 인터랙션 원리를 참고하되 본문·도표·이미지·코드 자산은 독자 작성하거나 명시적인 사용 허용 범위 안에서만 활용한다. roadmap.sh는 공식 소개에서 콘텐츠 재배포를 허용하지 않는다고 안내한다. 학습 자료는 원문 링크로 연결하고 ArchDeck의 설명·예제·다이어그램을 별도로 제작한다. [roadmap.sh 콘텐츠 이용 안내](https://roadmap.sh/about/)

보안·인증 설명의 사실 검증은 제품 벤치마킹과 별도로 원 규격·공식 제품 문서에 대조한다. ‘완전 차단’, ‘무조건 필수’, ‘1초 이내 보장’ 같은 단정은 적용 조건과 검증 근거가 있을 때만 사용한다.
