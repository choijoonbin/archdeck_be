# ArchDeck 누적 작업 계획

기준일: 2026-11-27 · 상태: 핵심 기능 구현·통합 검증 완료, Azure 회사망 확인·명시된 P2/확장 작업 잔여

기존 분석 결과와 DWP형 화면·설정 요구, 글로벌 벤치마킹, 사내 아이디·비밀번호 로그인 요구를 하나의 작업 목록으로 관리한다. 설계 파일이 준비됐다는 이유로 앱 기능을 완료 처리하지 않는다.

## 우선순위

P0는 화면 중단·데이터 손상·사내 접근 통제를, P1은 데이터 일관성과 필수 화면·설정·작성 기능을, P2는 학습 경험 확장을 다룬다. 현재 작업 상태는 설계 완료와 구현 대기를 구분한다.

## 기존 구현에서 확인한 근거

| 문제 | 확인 위치·행동 | 검증 범위 |
|---|---|---|
| 빈 흐름 화면 오류 | ArchitectureFlowViewer의 activeStep.step 참조와 DataInitializer의 빈 flowSteps | 서버 응답을 사용한 읽기 전용 React 렌더링에서 두 토픽 예외 재현 |
| 초기화 경합 | LearningContext가 연결 확인 즉시 저장 effect를 활성화하고 원격 상태를 별도 조회 | 코드상 경합 가능성 확인, 실제 개인 기록 손실을 주장하지 않음 |
| 공용 기록 | ArchDeckService의 DEFAULT_USER_ID=default_user | 브라우저가 달라도 같은 서버 레코드를 읽고 쓰는 구조 확인 |

| 콘텐츠 불일치 | FE 5/3/10/9, BE API 5/1/10/3 | 이전 읽기 전용 API 조회와 소스 대조. 토픽의 상세 내용도 다름 |

## 실행 순서

1. 현재 데이터·브라우저 백업과 실패 재현을 고정하고, 빈 흐름·초기 저장 경합·공용 기록 사용을 차단한다.
2. 새 PostgreSQL 구조와 JSON 계약을 확정하고 기존 콘텐츠를 변환·대조한다. 로그인용 계정·세션 구조와 초기 관리자 발급을 준비한다.
3. Spring Security 로그인·권한·CSRF와 같은 출처의 FE/API 경로를 구현한다. 이 단계의 접근 검증 후 사내 공유를 연다.
4. DWP형 shell과 테마 토큰을 도입하고 메뉴 배치·설정·헤더 로그인 상태를 구현한다.
5. 상세 URL·검색·필터·개인 기록 분리·작성 스튜디오·미리보기를 연결한다.
6. 흐름도·본문 용어·학습 경로를 보완하고 5개 토픽의 학습 여정을 통합 검증한다.

각 단계에서 관련 회귀 검증을 수행한다. 마지막에만 오류를 모아 처리하는 방식은 사용하지 않는다.

이번 작업에서 완료한 기반은 제품 기준과 벤치마킹, 메뉴·외관·인증 설계, 18개 테이블 DDL, Docker PostgreSQL 기동, 무결성 검사, 재시작 보존, 백업·별도 DB 복원 검사다. 실제 앱 통합 상태와 실행 근거는 [검증 결과](06-validation.md)에 구분해 기록한다.

## 범위 밖과 확장 조건

댓글·토론, Git/문서 웹훅, 공동 편집, 세밀한 권한 행렬, SSO, 외부 IAM, 여러 조직, 개인 기록의 자동 서버 동기화는 후속 결정이다. 필요성이 확인되면 기존 계정·revision·출처 모델을 확장한다. Redis·메시지 큐·Elasticsearch를 MVP의 필수 인프라로 추가하지 않는다.

## 통합 수용 조건

- 미로그인 상태에서 토픽·검색·용어·비교 API는 콘텐츠를 반환하지 않는다. 계정이 없는 사람에게 회원가입을 요구하지 않고 관리자 안내를 제공한다.
- 공유용 정적 번들·JSON·브라우저 캐시로 보호 콘텐츠를 우회 열람할 수 없다. 초기·재설정 비밀번호 사용자는 비밀번호 변경을 마쳐야 콘텐츠를 읽을 수 있다.
- 열람자는 게시된 지식을 읽고 개인 기록을 남길 수 있지만 콘텐츠·계정을 변경할 수 없다.
- 관리자만 스튜디오와 계정 관리에서 실제 서버 변경을 수행한다.
- 로그인 후 깊은 링크로 복귀하고, 로그아웃·세션 만료 시 화면과 민감 응답 캐시를 비운다.
- 각 테마와 메뉴 배치에서 7개 학습 메뉴, 설정, 검색과 상세 이동이 작동한다.
- API 중단·빈 데이터·저장 실패에서 화면을 계속 탐색하고 상태와 복구 행동을 이해할 수 있다.
- 학습 완료와 점검 결과를 구분하며 개인 기록은 브라우저·계정 사이에 섞이지 않는다.
- 새 토픽·용어·비교·점검을 데이터로 추가했을 때 목록·검색·상세·연관 이동에 반영된다.
- DB 백업을 별도 검증 DB에 복원하고 건수·관계·콘텐츠를 대조할 수 있다.

## 저장소 관리 위치

공통 기획·SQL·Docker 원본은 백엔드에 모으고 프론트는 링크로 참조한다. [저장소 구조](08-repository-layout.md)에 경로와 제외 기준을 기록한다. 제품 기능 구현 대기는 버전 관리 완료와 별개다.

## Agent 확장 기준

지정 분야 수집·지식화와 Azure OpenAI는 최신 추가 요구다. 원래 학습 서비스의 인증·데이터 P0를 유지하면서 별도 Agent 기반을 준비한다. 실제 수집·스케줄·모델 호출·자동 게시는 현재 활성화하지 않았다. 세부 실행 순서는 [Agent 계획](12-agent-implementation-plan.md), UX는 10, 데이터 계약은 11 문서를 따른다.

## 2026-11-27 실제 구현 기준

위 표의 설계 당시 구현 대기 상태는 이력으로 보존한다. 최신 실제 구현·검사·잔여 범위는 [구현과 통합 검증](13-implementation-and-verification.md)이 우선한다. P0·PostgreSQL·로그인·DWP shell/설정·Agent 수집/후보/게시 핵심 흐름을 구현했다. Azure 실제 접속은 사용자가 회사망에서 확인하기로 유예했다. 분산 연구 원장과 명시된 P2까지 완료한 것으로 해석하지 않는다.
