# ArchDeck 리서치 에이전트와 지식화 경험

기준일: 2026-11-27 · 상태: 추가 제품 설계, 화면·수집·모델 호출 구현 전

ArchDeck의 새 기능은 정한 분야의 변화를 수집하고 근거를 검토해 학습에 쓸 수 있는 지식으로 편집하는 흐름이다. 관리자는 수집 범위와 비용을 통제하고 초안을 검토하며, 열람자는 검토를 마친 인사이트에서 기존 토픽·비교·용어·점검으로 이어간다. 수집된 기사와 모델의 초안은 자동으로 게시하지 않는다.

이 문서는 사용자 경험과 데이터 계약의 제안이다. 최신 프레임워크와 하네스 관련 근거는 [아키텍처 검토](09-agent-architecture-research.md), 구체적인 실행·검토·저장 경계는 [데이터·API 운영](11-agent-data-api-and-operations.md), 기존 외관·로그인은 [기존 UX](02-product-and-navigation.md)와 [인증 설계](04-auth-and-sharing.md)를 따른다.

## 제품에서 구분할 세 가지 정보

| 정보 | 목적 | 보존·표시 방식 |
|---|---|---|
| 수집 근거 | 실제로 어떤 원문과 발표를 확인했는지 검토 | ADMIN의 검토함에서 출처 URL·발행일·수집일·허용된 인용·해시·수집 결과를 확인. 미검토 원문을 열람자 피드에 바로 노출하지 않음 |
| 트렌드·인사이트 | 최근 무엇이 바뀌었고 기존 판단에 어떤 영향을 주는지 설명 | 검토 후 게시한 시점성 콘텐츠. 사건일·발행일·적용 버전·검토일과 관련 지식을 함께 표시 |
| 영구 지식 | 이후에도 재사용할 개념·구성·비교·검증 방법을 제공 | 기존 토픽·용어·비교·체크리스트에 새 초안을 만들거나 변경 제안. 출처와 변경 이유를 보존 |

기사 한 편의 요약이 곧 영구 지식이 되지는 않는다. 원문의 사실, 작성자의 의견, ArchDeck의 해석·적용 제안을 분리한다. 여러 매체가 같은 발표를 재인용한 경우에는 독립된 다수의 근거로 계산하지 않는다.

## 대상 사용자와 중심 행동

| 사용자 | 해결할 질문 | 중심 행동 | 화면 유형 |
|---|---|---|---|
| 사내 READER | 지금 우리 분야에서 무엇이 바뀌었고 무엇을 다시 봐야 하는가 | 검토된 인사이트를 읽고 관련 학습·비교·점검으로 이동 | 필터 목록·상세 |
| ADMIN 운영자 | 무엇을 어디까지 수집하며 비용과 실패를 어떻게 제어하는가 | 분야·출처·규칙을 구성하고 실행·중지·재시도 | 운영 목록·설정 폼 |
| ADMIN 검토자 | 이 초안을 신뢰할 수 있고 어떤 형태로 게시해야 하는가 | 주장과 근거를 대조하고 편집·보류·승인 | 목록·증거 상세·변경 비교 |

같은 ADMIN이 운영과 검토를 맡을 수 있다. 작은 사내 서비스에 별도 승인자 역할이나 두 사람 승인을 필수로 추가하지 않는다. 누가 어떤 규칙·근거·초안 버전을 검토하고 게시했는지는 기록한다.

## 메뉴와 홈에 통합

기존 학습 메뉴 6개는 유지하고 시간성 콘텐츠의 진입점으로 트렌드·인사이트를 추가한다. 운영자가 쓰는 리서치 에이전트와 콘텐츠 스튜디오는 책임이 다르므로 관리 도구 안에서 분리한다.

```text
학습 탐색
  학습 시작
  트렌드·인사이트
  아키텍처
  비교
  용어 사전
  체크리스트
  내 서재

관리 도구 — ADMIN
  리서치 에이전트
  콘텐츠 스튜디오
  계정 관리
```

홈은 기존 이어 학습과 추천 경로를 먼저 유지하고 그 아래에 최근 검토된 변화 최대 3개를 둔다. 각 항목에는 분야, 무엇이 바뀌었는지 한 줄, 사건·발행일, 관련 토픽을 표시한다. 항목 수·누적 호출 수를 전면 KPI로 배치하지 않는다. 읽을 만한 게시 인사이트가 없으면 이 영역을 비워 두고 기존 학습을 계속 안내한다.

헤더의 검색·로그인 상태·로그아웃·설정은 그대로 사용한다. 알림 벨·푸시·메일 알림은 추가하지 않는다. 검토 대기 수와 실행 오류는 리서치 에이전트 화면 안에 표시한다. 좌·우·상단 메뉴와 축소 레일에서도 새 메뉴가 같은 선택·키보드·접근성 규칙을 따른다.

| 경로 | 사용자와 용도 | URL 상태 |
|---|---|---|
| `/insights` | 인증된 사용자의 게시 인사이트 목록 | `domain`, `q`, `period`, 반복 가능한 `tag`, `sort` |
| `/insights/:slug` | 검토된 변화·근거·관련 지식 | 원래 목록으로 돌아갈 내부 경로 |
| `/research` | ADMIN 운영·검토 진입 | `view=review\|runs\|profiles\|sources`, 분야·상태 필터 |
| `/research/profiles/:id` | 분야·규칙·일정·예산 설정 | 설정 탭과 버전 |
| `/research/runs/:id` | 실행 상태·결과·중지·재시도 | 선택 단계와 결과 필터 |
| `/research/reviews/:id` | 근거와 초안·기존 지식 변경 대조 | 검토 탭, 선택 주장·출처 |
| `/studio/:type/:id/edit?proposal=:id` | 검토 중인 제안의 정식 편집 | 기본 콘텐츠 버전과 제안 ID |

`/research`는 웹 UI 경로이며 Agent 서버 주소를 브라우저에 직접 연결하는 뜻이 아니다. 화면은 기존 BE의 인증·ADMIN 검사 API를 통해 실행과 검토를 수행한다. 상세 URL 재방문·로그인 복귀·뒤로가기는 기존 라우팅 계약을 따른다.

## 관리자의 최소 여정

1. 분야 하나를 선택해 허용 출처·포함/제외 키워드·기간·상한을 작성한다.
2. 규칙 미리보기에서 예시 기사 몇 개가 포함·제외되는 이유와 예상 요청 범위를 확인한다. 유료 모델 호출이 들어가는 미리보기는 실행 전에 비용 여부를 구분한다.
3. 수동 실행으로 수집을 시작한다. 실행 중에는 현재 단계·처리 수·실패 출처·누적 사용량과 중지 동작을 확인한다.
4. 검토함에서 묶인 사건·중복 기사·근거가 부족한 주장을 확인한다. 원문을 확보하지 못했으면 어떤 부분까지 확인했는지 표시한다.
5. 인사이트 초안, 새 영구 지식 초안, 기존 지식 변경 제안 중 적합한 결과를 선택한다. 제안만 있고 실제 변경이 없으면 승인할 필요 없이 보류·제외할 수 있다.
6. 근거·표현·적용 범위를 고친 뒤 미리보기에서 검토한다. 마지막 기본 동작은 **승인하고 게시**이며 검증을 통과한 정확한 초안·근거·기존 콘텐츠 버전에 적용한다. 사전 승인과 게시를 두 번 강제하지 않는다.
7. 게시 후에는 인사이트 상세와 관련 학습 콘텐츠에서 같은 출처와 변경 이유를 확인한다. 나중에 오류가 확인되면 철회·개정한다.

실행 완료는 수집·정리가 끝났다는 뜻이다. 검토 완료나 게시 완료와 같은 상태로 표시하지 않는다. 자동 게시 기본값은 꺼짐이며 모델에게 게시·계정 관리 권한을 주지 않는다.

## 분야와 수집 규칙

사용자가 정한 초기 범위는 기존 인증·보안·웹 아키텍처와 AI 에이전트다. 이 범위의 시작 프리셋을 제공하되 분야·출처·규칙은 데이터 설정으로 추가한다. 코드의 switch나 고정 enum에 분야를 넣어 확장을 막지 않는다. 같은 수집·근거·검토·게시 계약을 모든 분야에 적용하고, 분야별로 포함/제외·출처·품질 조건을 달리 저장한다. 수동 파일럿은 프리셋 하나에서 시작한 뒤 같은 계약으로 범위를 늘리는 안을 제안한다.

| 설정 | 초기 제안과 동작 |
|---|---|
| 분야 | 이름·목적·담당 검토자·연결할 기존 분류·태그 |
| 출처 | ADMIN이 승인한 도메인과 RSS/API/문서 경로. 공식 릴리스·표준·공식 기술 문서부터 시작 |
| 포함·제외 | 키워드·기술명·제품 버전·문서 종류, 광고·채용·반복 보도·의견 글의 처리 기준 |
| 기간 | 기본 최근 7일 제안. 원문 발행일·사건일과 수집일을 별도로 보존 |
| 언어 | 원문 언어를 유지하고 한국어 설명을 생성. 번역된 해석을 원문 직접 인용으로 표시하지 않음 |
| 실행 | 최초에는 수동. 반복 수집은 규칙 미리보기와 파일럿 검증 후 사용자가 켜는 제품 서버 일정 |
| 시간대 | Asia/Seoul을 기본으로 제안하고 화면에 다음 실행 시각·시간대 표시 |
| 수집 상한 | 실행당 출처 10개·후보 20개·초안 5개를 시작값으로 제안. 실제 처리량·품질을 보고 조정 |
| 비용·시간 | 모델별 최신 단가를 확인한 실행 예산·토큰·요청·벽시계 시간 상한. 단가 미확인·키 미설정이면 유료 실행 차단 |
| 재실행 | 같은 기간·규칙 버전의 중복 수집과 중복 초안을 줄이는 키·체크포인트. 재시도 범위와 추가 비용 표시 |
| 게시 | 수동 검토·게시. 규칙·프롬프트·모델 변경만으로 자동 게시가 켜지지 않음 |

모델 제공자는 사용자 지시에 따라 DWP Agent와 같은 Azure OpenAI 설정을 사용한다. 키·endpoint·deployment는 Agent 서버 환경에서 관리하며 브라우저 입력·번들·응답·trace로 보내지 않는다. ADMIN 화면에는 마스킹한 설정 상태, deployment 이름과 실제 확인한 기능 지원 여부를 표시한다. 공개 OpenAI API 직접 연결을 기본으로 선택하거나 Azure 배포가 모든 Responses 기능을 지원한다고 가정하지 않는다. 서버 설정 규약은 DWP Agent의 provider 코드와 맞추고 실제 자격증명을 문서·예시 파일에 복제하지 않는다.

매일 오전 9시 수집 같은 일정은 운영 시 선택할 예시다. 이 설계 작업에서 실제 크론·Codex 자동화·외부 유료 호출을 생성하지 않는다. 제품의 수집 일정과 사용자 채팅의 자동화는 다른 기능이다.

출처 추가는 즉시 전체 크롤링 승인이 되지 않는다. 허용된 경로·이용 조건·빈도·페이월·원문 저장 허용 범위를 기록하고, 출처가 차단되거나 정책이 바뀌면 해당 수집을 중지한다. 원문 전체를 열람자에게 재배포하기보다 허용된 근거 위치·짧은 인용·독자적 요약·원문 링크를 제공한다.

현재 `ArchDeck_Agent/config/domain-presets.json`은 `proposal-not-active`인 예시 설정이다. 실제 도메인이 기재되어 있어도 수집 허용·이용 조건 검토나 활성 일정이 승인됐다는 뜻은 아니다. `live_collection_enabled`, `schedule_enabled`, `auto_publish`는 모두 꺼진 상태를 유지한다. 출처별 정책·배포 기능·예산·BE 검토 계약이 준비된 뒤 활성화한다.

## 정보의 질과 최신성 표현

최신성은 발행일 하나로 판단하지 않는다. 사건일, 최초 발행일, 원문 수정일, 수집일, 관리자 검토일과 적용 제품 버전을 구분한다. 오래된 기사가 수정 날짜만 새로 바뀌었으면 새로운 사건으로 올리지 않는다. 날짜를 확인하지 못했으면 발행일 미확인으로 표시하고 수집일로 대체하지 않는다. 미래 날짜·출처 간 날짜 충돌은 검토 사유로 남긴다.

순위는 분야 관련성, 실제 변화 여부, 근거 품질, 독립된 근거의 수, 날짜 확인, 기존 지식에 미치는 영향을 조합하는 설명 가능한 규칙으로 제안한다. 초기에는 가중치나 점수를 확정값처럼 노출하지 않고 선정 이유를 보여 준다. 숫자로 된 모델 확신도를 사실 정확도의 확률로 표시하지 않는다.

| 주장 표시 | 의미 |
|---|---|
| 근거 확인 | 연결된 원문에서 주장을 뒷받침하는 위치를 확인함 |
| 추가 확인 필요 | 원문·날짜·범위가 불완전하거나 출처끼리 다름 |
| 의견·전망 | 출처 또는 ArchDeck의 해석·예상이며 확정된 사실이 아님 |
| 반영 검토 | 기존 토픽·비교·점검 항목에 어떤 변경이 필요한지 제안함 |

단일 공식 릴리스가 버전 출시를 설명하는 데 충분할 수 있으므로 모든 주장을 두 출처 이상으로 강제하지 않는다. 공식 발표의 존재를 시장 전체의 채택·우월성으로 확장하지 않는다. 일반적인 글로벌 트렌드 판단에는 서로 독립된 복수 근거와 반대·제약 요인을 함께 검토한다.

## 검토함과 변경 제안

검토함의 한 행은 원문 한 개가 아니라 같은 사건·변화를 묶은 검토 단위다. 제목·분야·사건일·근거 상태·관련 지식·미해결 문제·마지막 실행을 표시하고 선택하면 근거와 초안이 함께 열린다. 장식용 상태 점수보다 게시를 막는 문제와 다음 행동을 먼저 보여 준다.

검토 상세에는 주장별 출처 링크·근거 위치, 허용된 짧은 발췌, 확인한 날짜·버전, 번역/해석 표시, 중복 묶음과 제외 이유를 제공한다. 외부 원문은 별도 탭에서 열 수 있고 돌아왔을 때 선택한 주장·스크롤을 보존한다. 신뢰하지 않는 HTML·스크립트·원문의 지시문을 실행하지 않고 텍스트·허용된 마크업으로 렌더링한다.

관리자는 편집·추가 수집·보류·반려 또는 **승인하고 게시**를 선택한다. 반려·보류는 이유를 남기며 다음 실행에서 같은 초안이 이유 없이 다시 쌓이지 않게 한다. 출처 부족·날짜 충돌·스키마 오류·허용되지 않은 원문 사용은 게시를 막는 사유로 구분한다. 모델이 스스로 평가했다는 사실만으로 게시 조건을 통과하지 않는다.

기존 지식 변경은 게시된 내용과 제안 diff를 나란히 보여 주고, 각 변경의 근거와 대상 `baseLockVersion`을 보존한다. 검토 중 기존 문서가 수정되면 자동 덮어쓰기 대신 충돌을 표시한다. 새 버전으로 차이를 다시 확인하기 전 이전 화면에서 게시할 수 없다. 모델·규칙·근거·초안을 다시 생성하면 게시 대상 버전도 다시 확인해야 한다.

게시의 명시적 계약은 `POST /api/research/candidates/{id}/publish`다. `candidateVersion`, `baseLockVersion`과 멱등 키를 고정하고, BE가 근거·권한·현재 버전을 검증한 뒤 승인 기록과 정규 콘텐츠·출처·revision을 같은 트랜잭션으로 저장한다. `/review`는 반려·수정 요청·의견 기록이며 단순 승인 상태를 저장했다고 묵시적으로 게시하지 않는다. 이 API의 사용자·내부 경계와 오류 응답은 데이터·API 문서에서 관리한다.

게시 결과는 인사이트·새 토픽·용어·비교·점검 중 하나 이상으로 연결할 수 있지만 동일 내용을 여러 종류에 복제하지 않는다. 인사이트는 최근 변화와 영향, 영구 지식은 재사용 가능한 설명을 담당한다. 원문이 수정·철회되거나 오류 신고가 오면 영향받는 콘텐츠를 찾아 검토 필요로 표시하고 필요 시 게시를 철회한다. 과거 버전과 결정 이유는 관리자 이력에 남긴다.

## 열람자의 인사이트 경험

목록에서 분야·기간·태그·관련 기술로 좁히고 왜 이 변화가 중요한지 한 줄을 읽는다. 정렬은 검토된 최근 변화가 기본이며 조회 수나 모델의 추천 확률을 기본 기준으로 삼지 않는다. 단순 링크 모음이나 기사 전문 복제 화면으로 만들지 않는다.

상세 순서는 무엇이 바뀌었나 → 누구에게 어떤 영향이 있나 → 확인된 근거와 남은 불확실성 → 기존 방식과의 차이 → 관련 학습·검증 → 출처·검토 이력이다. AI 초안을 사용했다는 사실과 관리자 검토일을 표시하되 검토 배지를 정확성 보증으로 표현하지 않는다.

본문의 용어는 기존 사전을 재사용하고 관련 토픽·비교·체크리스트로 연결한다. 검색에는 게시된 인사이트만 포함한다. 실행 로그·미검토 후보·초안·관리자 검토 근거 파일은 READER 검색·번들·내보내기에 섞이지 않는다. 북마크와 메모는 기존의 계정별 브라우저 저장을 사용하며 별도 트렌드 계정을 만들지 않는다.

## 실행 상태와 실패 처리

| 상태 | 화면의 안내와 행동 |
|---|---|
| 아직 실행 없음 | 규칙을 작성하고 미리보기·수동 실행으로 시작 |
| 수집·정리 중 | 현재 단계·처리 범위·누적 사용량, 중지 동작 |
| 일부 출처 실패 | 성공한 결과 유지, 실패 출처·사유·선택 재시도. 일부 실패를 0건으로 표시하지 않음 |
| 검토 후보 없음 | 검색 결과 없음, 전부 중복, 규칙에서 제외를 구분하고 실행 성공 여부 표시 |
| 예산·시간 상한 | 더 이상 호출하지 않고 중지 이유·보존 결과·재개 조건 표시 |

| 검토 대기 | 확인해야 할 문제와 초안으로 이동. 실행 완료와 게시 완료를 구분 |
| 게시 후 변경 필요 | 새 근거·철회 사유와 영향받는 게시 콘텐츠로 이동 |

재시도는 실패한 단계·출처만 선택하는 것을 기본으로 한다. 완료된 원문 수집·모델 호출·초안 작성을 전부 반복하지 않도록 실행 버전과 체크포인트를 사용한다. 구체적인 지속 실행·저장 구현은 Agent 아키텍처 계약을 따른다. 키·모델·수집 서버 상태 같은 기술 상세는 ADMIN 실행 상세에 두고 학습 화면에는 노출하지 않는다.

## 권한과 데이터 경계

사용자 인증과 검토·게시 권한의 주체는 BE다. READER는 게시 콘텐츠만 열람하고 ADMIN은 규칙·실행·근거·초안을 관리한다. Agent는 허용 출처 수집, 추출·분류·중복 처리·초안·검증 보고만 수행한다. 게시 콘텐츠를 직접 수정하거나 사용자·세션을 관리하는 도구 권한을 주지 않는다.

LLM·외부 도구로 보낼 데이터는 허용된 공개 근거와 작업에 필요한 최소한의 콘텐츠로 제한한다. 계정·세션·API 키·개인 메모·개인 학습 기록·작성자의 비공개 초안을 자동 전송하지 않는다. 사내 게시 콘텐츠라도 외부 모델 전송 허용을 별도로 정하지 않았다면 외부 전송 대상으로 간주하지 않는다. 게시할 수 있다는 사실과 외부 서비스에 전송할 수 있다는 사실을 분리한다.

원문의 지시문은 수집 대상 데이터다. 출처 추가·자격증명 요청·다른 도메인 호출·게시 동작을 유도해도 규칙이나 도구 권한을 바꿀 수 없다. 차단된 요청은 검토자에게 이유를 보여 주되 로그·화면에 비밀값을 남기지 않는다.

| 계약 | 필요한 내용 |

## 아직 확정하지 않은 운영 선택

초기 분야와 Azure OpenAI 사용은 확정됐다. 분야 안의 세부 포함/제외 주제, 허용 출처 목록, 외부 모델 전송 범위, 사용할 Azure deployment와 확인된 기능, 비용 상한, 보존 기간, 반복 수집 주기는 운영 설정에서 확정해야 한다. 그 전까지 제안값은 수동 파일럿의 검토 기준이며 실제 자동 수집·유료 실행의 승인으로 취급하지 않는다.

자동 게시, 이메일·푸시 알림, 소셜 피드, 공개 댓글, 모든 웹의 무제한 크롤링, 자율 브라우저 로그인, 유료 원문 우회, 개인 메모의 자동 분석은 초기 범위에 넣지 않는다. 새로운 수집·지식화 기능은 기존 로그인·참조·저장 안정화와 함께 검증한 뒤 사내 서비스에 연다.

## 초기 실행 골격과 제품 완료의 구분

현재 Agent 서버의 상태 확인·합성 fixture 평가와 Azure 요청 어댑터는 개발용 기반이다. 합성 평가의 `fixture_only=true`, `published=false`, `external_calls=0`은 실제 최신 기사·모델 사실 검증·게시가 수행되지 않았음을 나타낸다. `/readyz`가 의도적으로 503을 반환하는 상태를 운영 준비 완료로 표시하지 않는다.

이 문서의 화면·실수집·예산 집행·영속 checkpoint·BE 검토·게시는 구현해야 할 계약이다. fixture에서 일부 규칙이 통과한 것을 모든 RUX 조건의 성공으로 보고하지 않는다. 게시 API와 실제 승인 동작을 연결하기 전까지 UI의 실행 완료·검토 의견 기록·게시 완료를 구분한다.
