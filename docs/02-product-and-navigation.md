# ArchDeck 제품 기획과 메뉴 설계

작성일: 2026-11-27 KST. 상태: 초기 개발을 위한 기획 기준안. 이 문서는 현재 구현과 앞으로 구현할 설계를 구분한다.

ArchDeck은 개발자가 아키텍처의 동작을 이해하고, 대안을 비교하고, 자신의 시스템에 적용할 조건을 검증하는 기술 학습 도구다. 시작 콘텐츠는 IAM·OIDC·SPA와 BFF·웹 보안이며, 동일한 구조에 다른 주제를 추가할 수 있어야 한다. 학습의 단위는 토픽, 토픽을 설명하는 흐름, 비교 기준, 용어, 검증 항목의 연결이다.

핵심 여정은 **질문 찾기 → 그림과 단계로 이해하기 → 대안 비교하기 → 검증 항목 확인하기 → 내 기록 남기기**다. 전역 메뉴는 이 여정의 진입점을 제공하고, 상세 화면에서는 문맥을 유지한 채 다음 단계로 연결한다.

## 확정 요구와 이번 설계의 선택

| 구분 | 내용 |
|---|---|
| 사용자 최신 확정 | 사내 열람을 위해 단순 아이디·비밀번호 로그인과 헤더 로그인 진입을 제공한다. 로그인 후 이름과 로그아웃을 표시한다. 알림 아이콘은 두지 않는다. |
| 사용자 확정 | DWP의 사이드바·헤더 스타일과 구조를 참고한다. |
| 사용자 확정 | 색상·외관 preset, 메뉴 왼쪽·오른쪽·상단 배치, 메뉴 접기, 주간·야간 전환을 제공한다. |
| 기존 명세 유지 | React·TypeScript·Tailwind, 단계별 학습, 비교, 용어, 체크리스트, 코드 복사, 북마크·진도·메모, 작성·미리보기·JSON 입출력. |
| 사용자 확정 | 개인 로컬 사용이 중심이며, 필요하면 로컬 서버를 사내 동료와 공유한다. 콘텐츠는 호스트 서버에서 공유한다. |
| 기준안 | 하나의 같은 출처 서비스에서 ADMIN은 계정·콘텐츠를 관리하고 READER는 인증 후 콘텐츠를 열람한다. 관리자는 주로 호스트 PC에서 운영하되 사내 HTTPS에서도 역할에 따라 접근한다. |
| 기준안 | 학습 기록과 화면 설정은 브라우저 + 로그인 계정별로 보관한다. 기존 공용 `default_user` 저장을 개인 기록의 기준으로 사용하지 않는다. 서버 동기화는 후속 범위다. |
| 기준안 | 글로벌 서비스의 구조·상호작용 원리를 참고하고 원문·그림·브랜드는 복제하지 않는다. |
| 기준안 | DWP의 화면 구조와 외관 원리를 Tailwind로 구현한다. DWP의 인증·테넌트·알림·MUI 의존성은 ArchDeck에 가져오지 않는다. |

사내 공유에서는 로그인한 READER에게 읽기를 제공하고 ADMIN에게 작성·계정 관리를 허용한다. 메뉴 표시와 별도로 서버 API가 역할을 검사해야 한다. ADMIN을 LAN에서 차단하기 위한 별도 작성 서비스·별도 읽기 서비스는 MVP에 추가하지 않는다. 백엔드와 DB는 loopback·내부 연결에 두고 LAN에는 같은 출처의 HTTPS 진입점을 제공한다. 회원가입·SSO·Keycloak 기반 앱 인증·JWT 기반 복잡한 인증 구성은 초기 범위에 포함하지 않는다. Keycloak과 OIDC는 계속 학습 콘텐츠로 제공한다. API에서 사용하는 실제 세션 방식과 보호 정책은 데이터·백엔드 설계의 계약을 따른다.

## 사용자와 해결할 질문

| 사용자 | 해결할 질문 | 대표 행동 | 화면 유형 |
|---|---|---|---|
| 주 사용자: 프론트엔드·풀스택 개발자 | SPA에서 직접 인증할지 BFF를 둘지 어떻게 판단하는가? | 흐름을 이해하고 비교에서 조건을 선택한다. | 목록·상세, 단계 흐름, 비교 |
| 주 사용자: 실무 개념을 학습하는 개발자 | PKCE·JWKS·CSRF가 실제 요청 과정에서 어디에 쓰이는가? | 설명의 용어를 열고 같은 단계로 돌아온다. | 상세, 문맥 팝오버 |
| 보조 사용자: 설계를 검토하는 개발자·리드 | 현재 설계에서 빠뜨린 방어·운영 항목은 무엇인가? | 체크리스트를 검토하고 로컬 수행 기록을 남긴다. | 검증 목록 |
| 작성자: 초기에는 프로젝트 운영자 | 새 주제를 일관된 형식과 근거로 추가할 수 있는가? | 콘텐츠 스튜디오에서 검증·미리보기 후 저장한다. | 작성 스튜디오 |

면접 문제은행, 범용 노트 앱, IAM 제품 관리 콘솔, 소셜 커뮤니티, 실시간 팀 협업은 초기 제품 범위가 아니다.

## 메뉴 구조

학습 탐색에는 6개 메뉴를 둔다. 흐름도는 아키텍처 상세 안에 포함하여 같은 내용을 찾는 메뉴가 중복되지 않게 한다. 콘텐츠 스튜디오와 계정 관리는 ADMIN 도구 그룹으로 분리한다. 설정은 헤더에서 접근할 수 있다.

```text
ArchDeck
  학습 시작
  아키텍처
  비교
  용어 사전
  체크리스트
  내 서재

관리 도구 — ADMIN에서 표시
  콘텐츠 스튜디오
  계정 관리

헤더 공통 동작
  통합 검색 · 새 지식 · 전체화면 · 설정 · 로그인 또는 이름과 로그아웃
```

| 메뉴 | 사용자가 얻는 결과 | MVP에 포함할 화면 | 표시 원칙 |
|---|---|---|---|
| 학습 시작 | 지금 읽을 주제를 정하고 이전 학습을 이어간다. | 계속 학습, 추천 순서, 주요 비교·검증 진입, 최근 본 항목 | 미완료 항목과 다음 행동을 먼저 보여 준다. |
| 아키텍처 | 특정 설계의 문제·구성·동작·적용 조건을 이해한다. | 토픽 목록, 토픽 상세, 구성도, 단계 흐름, 코드·근거 | 기술영역·태그로 좁히고 상세로 이동한다. |
| 비교 | 선택 조건에 따라 대안의 차이를 판단한다. | 비교 목록, 비교 매트릭스, 적용 조건과 판단 근거 | 토픽 상세에서도 해당 비교로 연결한다. |
| 용어 사전 | 문맥과 연결된 정의를 빠르게 찾는다. | 검색·분류 목록, 단일 용어 상세, 연관 토픽 | 등록 용어는 본문 팝오버에서 같은 상세로 연결한다. |
| 체크리스트 | 적용 전 확인할 항목과 검증 방법을 찾는다. | 목적별 점검 목록, 단일 항목 상세, 우선순위·상태 필터, 검증 방법·코드·근거 | 콘텐츠와 개인 수행 결과를 분리한다. |
| 내 서재 | 북마크·학습 기록·메모를 다시 활용한다. | 북마크, 학습 중·완료, 최근 기록, 메모, 백업·복원 | 브라우저에 보관된다는 점을 저장 안내에서 설명한다. |
| 콘텐츠 스튜디오 | 완성된 구조의 콘텐츠를 작성·검증한다. | 유형 선택, 초안 목록, 구조 편집, 미리보기, JSON 입출력 | ADMIN에 제공하며 서버 역할 검사로 보호한다. |
| 계정 관리 | 사내 열람 계정을 만들고 관리한다. | 아이디·표시 이름·역할·사용 상태, 비밀번호 재설정·비활성화 | ADMIN만 사용하며 자가 회원가입·계정 삭제는 제공하지 않는다. |

## 경로와 상태 보존

프론트 경로와 `/api` 경로는 별개의 계약이다. 기존 `/api/topics`, `/api/comparisons`, `/api/glossary`, `/api/checklists` 호환을 유지하면서 프론트 라우팅을 도입한다. 현재 `currentView`만 바꾸는 방식은 상세 URL을 가진 라우팅으로 전환한다. 초기 데이터의 ID는 이관 중에도 유지하고, slug 변경 시 이전 경로를 새 경로로 연결한다.

| 프론트 경로 | 용도 | URL에 보존할 상태 |
|---|---|---|
| `/login` | 아이디·비밀번호 로그인 | 검증된 내부 `returnTo` 경로 |
| `/change-password` | 초기 발급·관리자 재설정 후 비밀번호 변경 | 검증된 내부 복귀 경로. 변경 완료 전 일반 콘텐츠 진입 제한 |
| `/` | 학습 시작 | 선택한 학습 경로가 있을 때 경로 ID |
| `/paths/:slug` | 후속 P2의 독립 학습 경로 화면 | 선택한 경로 항목. 전역 메뉴는 학습 시작을 활성화 |
| `/topics` | 아키텍처 목록 | `q`, `category`, 반복 가능한 `tag`, `sort` |
| `/topics/:slug` | 토픽 상세 | `tab=overview\|flow\|tradeoffs\|code\|checklist`, `step`, `snippet` |
| `/comparisons` | 비교 목록 | `q`, `category`, 반복 가능한 `tag` |
| `/comparisons/:slug` | 단일 비교 | 선택한 비교 대상, 강조 차원 |
| `/glossary` | 용어 목록 | `q`, `category`, 반복 가능한 `tag` |
| `/glossary/:slug` | 단일 용어 | 원래 토픽으로 돌아갈 내부 경로 |
| `/checklists` | 체크리스트 목록 | `q`, `category`, `priority` |
| `/checklists/:slug` | 단일 점검 항목의 검증 방법·근거 | 돌아갈 목록의 검색·분류·우선순위 상태 |
| `/library` | 내 서재 | `view=bookmarks\|progress\|notes\|recent` |
| `/studio` | 초안·콘텐츠 관리 | 콘텐츠 유형, 초안 상태 |
| `/studio/:type/new` 또는 `/studio/:type/:id/edit` | 새 콘텐츠·기존 콘텐츠 편집 | 편집 탭, 미리보기 상태 |
| `/admin/users` | ADMIN의 계정 관리 | 검색어, 역할·사용 상태 필터 |
| `/search` | 전체 검색 결과 | `q`, 콘텐츠 유형, 분류, 반복 가능한 `tag`, `sort` |

설정 패널은 어느 경로에서나 `settings=appearance`, `settings=navigation`, `settings=data`로 열 수 있게 한다. 닫으면 원래 페이지·필터·스크롤 위치를 복원한다. 좁은 화면에서는 같은 패널을 전체 높이로 표시한다.

로그인 화면은 아이디·비밀번호·로그인 버튼으로 구성한다. 실패 시 계정 존재 여부를 드러내지 않는 동일한 오류 문구를 보여 준다. `returnTo`는 허용된 동일 출처의 앱 경로만 처리하고 외부 URL은 사용하지 않는다. 보호된 상세 링크에서 로그인하면 원래 상세·필터·단계로 돌아온다. 로그인 제출 중 중복 전송을 막고, 세션 만료·권한 없음·네트워크 실패를 서로 구분한다. 비밀번호나 세션 자격 증명을 브라우저 개인 기록 저장소에 넣지 않는다.

## 로그인과 세션의 화면 계약

현재 프론트엔드는 토픽·비교·용어·체크리스트 원본을 JavaScript 번들에 포함한다. 이 상태에서는 API에만 로그인을 붙여도 배포된 번들에서 콘텐츠를 읽을 수 있다. 사내 공유 전에는 게시 콘텐츠·초안·검색 메타데이터를 인증된 API로만 공급하고, 미인증 상태의 빌드 산출물·검색 인덱스·오프라인 캐시에 보호할 콘텐츠가 포함되지 않게 해야 한다. 로고와 일반적인 메뉴 이름 등 공개 가능한 화면 틀만 로그인 전에 제공한다.

| 상황 | 화면 행동 |
|---|---|
| 처음 방문·미로그인 | 로그인 화면. 콘텐츠 본문·검색 결과·초안을 미리 불러오지 않음 |
| 로그인 성공 | 해당 계정의 브라우저 기록·설정을 불러온 후 허용된 상세 경로로 이동 |
| 로그인 실패 | 아이디 존재 여부·비활성 상태를 구분하지 않는 오류와 재시도 안내. 입력한 아이디는 유지하고 비밀번호는 화면 정책에 따라 처리 |
| 세션 만료·로그아웃 | 보호 콘텐츠와 검색·미리보기·메모의 화면·메모리 캐시를 즉시 내리고 로그인으로 이동. 이전 계정의 늦은 응답을 새 계정 상태에 반영하지 않음 |
| 권한 없음 | 로그인 화면으로 반복 이동시키지 않고 권한 안내와 열람 가능한 목록으로 돌아가기 제공 |
| 네트워크 실패 | 세션 만료와 구분하여 재시도 제공. 인증 전 내장 시드나 다른 계정의 캐시를 대신 표시하지 않음 |

자체 회원가입은 없다. 첫 관리자 계정은 호스트 운영자가 초기 설정 절차에서 한 번 발급하고, 재시작할 때마다 초기 비밀번호로 덮어쓰지 않는다. 초기 발급값·비밀번호는 저장소의 시드·로그·화면 캡처에 포함하지 않는다. ADMIN은 계정을 추가하고 비밀번호를 재설정하며, 계정 삭제 대신 비활성화를 사용한다. 비활성화와 비밀번호 재설정에 따른 기존 세션 처리 규칙은 백엔드 인증 설계와 함께 검증한다.

초기·임시 비밀번호로 인증하면 `must_change_password`를 확인하여 `/change-password`로 이동한다. 비밀번호 변경을 마치기 전에는 일반 콘텐츠·검색·작성·계정 관리로 진입하지 못하며 서버도 동일하게 제한한다. 화면에는 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인과 변경 동작을 제공한다. 변경 성공 시 모든 기존 세션을 종료하고 새 비밀번호로 다시 로그인한 뒤 허용된 원래 경로로 돌아간다. 가입·프로필 편집으로 확장하지 않는 좁은 목적의 화면이다.

계정 생성·비밀번호 재설정은 Unicode code point 기준 15~128개와 UTF-8 최대 512바이트를 사용하고 한글·공백·붙여넣기·비밀번호 관리자를 허용한다. 로그인 입력에서 비밀번호를 임의로 trim하거나 문자열을 바꾸지 않는다. JavaScript UTF-16 길이를 그대로 비밀번호 글자 수로 사용하지 않고 서버와 동일한 code point·바이트 규칙을 적용한다. 신규 계정은 Argon2id 저장을 기본으로 하며 구체적인 매개변수는 `04-auth-and-sharing.md`에서 관리한다. 비밀번호 표시·숨기기는 접근 가능한 버튼으로 제공하고 로그인에는 `username`·`current-password`, 새 비밀번호에는 `new-password` 자동완성 의미를 지정한다.

모바일에서 상세 링크 → 로그인 → 원래 상세로 돌아오는 과정도 데스크톱과 같은 계약을 따른다. 복귀 경로는 로그인 성공 시 다시 검사하고, READER가 ADMIN 경로로 복귀하려 하면 권한 안내를 표시한다. 외부 URL·프로토콜 상대 URL·유효하지 않은 경로를 복귀 대상으로 사용하지 않는다. 비밀번호·CSRF 값·세션 자격 증명은 URL에 넣지 않는다.

## 통합 검색

검색의 빠른 진입은 Cmd/Ctrl+K 팝오버, 많은 결과를 탐색하는 곳은 `/search`다. 두 화면은 같은 결과 모델과 필터 규칙을 사용한다. 한 필터 안의 여러 태그는 OR, 콘텐츠 유형·분류·태그 등 서로 다른 필터 사이는 AND로 처리하고 이 규칙을 UI 도움말에 설명한다. 빈 검색어는 최근 검색·추천 항목을 보여 준다. 검색어는 URL 공유가 필요한 검색 화면 외에는 브라우저에만 보관한다.

모든 결과는 `contentType`, 안정적인 `id`, `slug`, `title`, `excerpt`, `category`, `tags`, `targetUrl`을 가진다. 토픽·비교·용어·체크리스트 결과에서 클릭과 Enter는 정확한 항목까지 이동해야 한다. 항목을 찾지 못하면 임의의 첫 토픽으로 바꾸지 않고 미존재 안내와 목록 복귀 동작을 제공한다.

## 홈과 학습 경로

홈의 첫 화면은 전체 콘텐츠 개수보다 다음 학습 행동을 우선한다. 기존 Bento 구성은 정보 위계를 위한 배치로 활용하고, 같은 크기의 카드와 장식 효과를 반복하지 않는다.

1. 이전 기록이 있으면 마지막 토픽과 단계에서 이어가기 버튼을 먼저 제공한다. 처음 방문했으면 인증 흐름 입문 경로의 시작점을 보여 준다.
2. 추천 경로는 `IAM 개요 → SPA+PKCE → BFF+Token Relay → SPA/BFF 비교 → XSS/CSRF와 검증`의 순서로 시작한다. 이미 이해한 토픽은 건너뛸 수 있다.
3. 직접 문제를 해결하려는 사용자는 비교·용어·체크리스트로 바로 갈 수 있다.
4. 최근 본 항목은 브라우저 기록의 실제 열람 순서를 사용한다. 추천과 최근을 같은 데이터처럼 표시하지 않는다.
5. 완료율은 현재 경로의 유효한 토픽을 분모로 계산한다. 삭제되거나 이동한 ID 때문에 100%를 넘지 않게 한다.

MVP는 홈과 토픽 상세에서 정해진 경로와 다음 학습 연결을 제공한다. 경로는 기존 토픽의 ID 참조와 순서를 보유하고 본문을 복제하지 않는다. 독립 경로 상세 화면(`/paths/:slug`), 별도 로드맵 편집기, 자유로운 그래프 편집, AI 추천은 후속 P2 범위다. ByteByteGo의 시각·단계 설명, roadmap.sh의 경로·진도, Refactoring.Guru의 일관된 상세 템플릿을 이 구조에 반영한다. 서비스 선정 근거와 공식 출처는 `01-benchmark.md`에서 관리한다.

## 상세 화면의 공통 템플릿

토픽의 기본 읽기 순서는 **해결할 문제와 사용 조건 → 전체 구성 → 단계별 동작 → 장단점·대안 → 검증 → 출처·검토일**로 통일한다. 사용자는 같은 위치에서 같은 종류의 정보를 찾을 수 있어야 한다.

| 영역 | 필수 내용 | 상호작용 |
|---|---|---|
| 문제와 조건 | 한 줄 결론, 해결할 문제, 언제 사용하는지, 사전 지식 | 관련 선행 토픽으로 이동 |
| 전체 구성 | 노드·역할·경계와 설명 | 노드 선택 시 연결된 설명 표시 |
| 단계 흐름 | 순서, 행위자·대상, 요청·응답, 보안 유의점 | 단계 버튼·이전/다음·선택적 재생, 노드·선 연결 강조 |
| 장단점과 대안 | 장점, 비용·제약, 대안과 선택 조건 | 비교 매트릭스의 해당 항목으로 이동 |
| 검증 | 관련 체크리스트와 검증 방법 | 검증 항목 상세로 이동 |
| 근거 | 공식 문서 링크, 적용 버전, 최근 검토일 | 출처 열기 |
| 개인 기록 | 북마크, 학습 상태, 메모 | 브라우저 저장, 백업·복원 |

모든 토픽에 흐름도가 필요한 것은 아니다. `diagramNodes`나 `flowSteps`가 비어 있으면 해당 영역을 생략하거나 ‘이 주제는 설명 중심입니다’와 연관 비교를 표시한다. 빈 배열을 채우기 위해 일반적인 가짜 요청 단계나 임의의 코드 예제를 자동 생성하지 않는다. 흐름이 있는 토픽의 모든 active node·edge 참조와 단계 순서는 저장 전에 검증한다.

흐름에는 연결선·요청 방향과 현재 단계를 함께 표시하고, 같은 정보를 순서 있는 텍스트로 제공한다. 재생은 사용자가 시작하며, 모션 축소 설정에서는 정적인 강조 전환을 사용한다. 토픽이나 단계 URL을 바꿨을 때 필드가 존재하지 않으면 안전한 탭·유효 단계로 이동하고 변경 이유를 알려 준다.

비교 화면은 실제 비교 대상 수에 맞춰 열 수를 정한다. 두 대안을 비교할 때 4열 그리드의 절반을 비워 두지 않는다. 넓은 화면에서는 항목명과 대상 헤더를 고정한 표, 좁은 화면에서는 평가 차원별로 대안 내용을 묶는다. 좋음·주의·위험 표시는 아이콘과 문구를 함께 사용하고, 어떤 조건에서 유리한지 근거를 제시한다.

용어 팝오버는 본문을 이탈하지 않고 핵심 정의·관련 단계·상세 링크를 보여 준다. 호버·클릭·키보드 포커스로 열 수 있어야 하며 Escape로 닫힌다. 긴 용어나 화면 가장자리에서도 팝오버가 잘리지 않게 한다. 같은 용어의 정의는 한 레코드에서 사용하고 본문마다 복제하지 않는다.

체크리스트는 ‘학습 완료’와 ‘실제 시스템 검증 통과’를 같은 상태로 취급하지 않는다. 서버에는 항목·우선순위·검증 방법·근거를 저장하고, 개인의 수행 기록에는 대상 이름, 확인 일시, 결과, 메모를 보관한다. 초기 수행 기록은 브라우저에 저장한다. 체크 여부만으로 보안 인증이나 규정 준수를 완료했다고 표현하지 않는다.

## DWP 스타일의 공통 화면 틀

공통 화면은 `AppShell`, `AppHeader`, `AppNavigation`, `PageContainer`, `SettingsPanel`의 책임으로 분리한다. 상세 데이터의 로딩과 개인 기록은 메뉴 배치와 독립적이어야 한다.

| 부분 | 설계 |
|---|---|
| 헤더 왼쪽 | 메뉴 열기·접기, ArchDeck 식별, 현재 메뉴·페이지 제목 |
| 헤더 오른쪽 | 통합 검색, 새 지식, 전체화면, 설정, 로그인 상태. 새 지식은 ADMIN에게 표시 |
| 사이드바 | 로고·접기 제어, 학습 탐색 6개 메뉴, 하단 ADMIN 도구. 선택한 메뉴와 자식 상세를 같은 활성 문맥으로 표시 |
| 본문 | 안정된 최대 폭과 반응형 격자. 읽기 문장은 좁게, 비교와 구성도는 필요한 폭을 사용 |
| 상태 안내 | 로딩·결과 없음·오류·재시도·읽기 전용 상태를 페이지 안에서 보여 줌 |

비로그인 상태의 헤더에는 로그인 버튼을, 로그인 후에는 표시 이름과 로그아웃 동작을 제공한다. 아바타나 별도 프로필 화면은 필수로 추가하지 않는다. 알림 아이콘과 계정 전환 기능은 두지 않는다. 설정은 로그인 상태 표시와 독립된 버튼으로 제공한다. API 프레임워크명이나 개발용 상태 배지를 주된 화면에 노출하지 않고, 저장 위치·실패·마지막 성공 확인 등 사용자 판단에 필요한 상태만 제공한다.

스타일은 DWP처럼 선명한 타이포 위계, 절제한 표면색, 얇은 구분선, 명확한 활성·포커스 상태를 사용한다. 장식용 글로우·배경 구체·상시 반복 애니메이션은 기본 표현에서 줄인다. Pretendard 본문과 JetBrains Mono 코드의 위계는 유지한다. DWP와의 일관성은 MUI 코드 복사보다 간격·행동·상태의 일관성으로 구현한다.

현재 DWP 공통 외관 소스는 `system/light/dark`, `compact/standard/comfortable`, 고대비·모션 축소와 `sidebar/rail/top` 패턴을 제공한다. 색상 preset 선택과 오른쪽 배치는 확인한 최신 DWP에 있는 기능을 그대로 이식하는 것이 아니라 ArchDeck에서 추가할 요구다. DWP의 사용자·테넌트 식별에 묶인 저장 키도 그대로 사용하지 않는다.

## 메뉴 배치와 반응형 동작

메뉴 배치와 펼침 여부를 서로 독립된 상태로 저장한다.

| 상태 | 넓은 화면 | 좁은 화면 |
|---|---|---|
| 왼쪽·펼침 | 왼쪽에 아이콘·메뉴명, 본문은 나머지 공간 | 왼쪽 드로어 |
| 왼쪽·축소 | 왼쪽 아이콘 레일, 포커스·호버 설명 | 왼쪽 드로어에서 메뉴명을 함께 표시 |
| 오른쪽·펼침 | 오른쪽에 아이콘·메뉴명 | 오른쪽 드로어 |
| 오른쪽·축소 | 오른쪽 아이콘 레일 | 오른쪽 드로어에서 메뉴명을 함께 표시 |
| 상단 | 헤더 아래 수평 내비게이션, 현재 메뉴 표시 | 메뉴 버튼으로 열리는 드로어 |

오른쪽 배치는 본문의 읽기 방향을 바꾸는 RTL 설정이 아니다. 한국어와 영문 본문은 원래 읽기 방향을 유지하고, 메뉴·본문의 물리적 위치와 경계만 바꾼다. 상단 배치에서는 사이드바를 위한 빈 폭을 남기지 않으며, 이전 사이드바 펼침 설정은 보존한다.

초기 경계는 1024 CSS px로 두되, 실제 콘텐츠 폭과 200% 확대에서 동작을 검증하여 조정한다. 모바일로 전환됐다고 저장된 데스크톱 배치 설정을 덮어쓰지 않는다. 드로어는 메뉴 선택·Escape·바깥 클릭으로 닫히고, 닫힌 뒤 열기 버튼으로 포커스가 돌아온다. 드로어와 설정 패널을 중첩하지 않으며 새 패널을 열면 기존 오버레이를 정리한다.

## 외관 설정과 저장 계약

화면 설정은 학습 기록과 별도의 버전 있는 데이터로 저장한다. 설정 복원 실패가 학습 기록을 지우면 안 된다.

```ts
interface AppearancePreferencesV1 {
  version: 1;
  mode: 'system' | 'light' | 'dark';
  preset: 'archdeck-cyan' | 'dwp-blue' | 'indigo' | 'emerald';
  navigation: {
    placement: 'left' | 'right' | 'top';
    collapsed: boolean;
  };
  density: 'compact' | 'standard' | 'comfortable';
  highContrast: boolean;
  reduceMotion: boolean;
}
```

프리셋 이름과 개수는 초기 설계안이다. 기본값은 `system`, `archdeck-cyan`, `left`, 펼침, `standard`, 고대비 꺼짐, 사용자 지정 모션 축소 꺼짐으로 제안한다. 운영체제의 모션 축소는 사용자 설정과 함께 반영한다. 사용자가 시스템 모드를 선택한 동안에는 OS 색상 변경을 따라가고, 명시적으로 주간·야간을 선택하면 해당 선택을 유지한다.

| 설정 | 동작 계약 |
|---|---|
| 색상 preset | 강조색과 선택·포커스·링크를 일관되게 바꿈. 성공·주의·오류 의미색은 별도로 유지 |
| 주간·야간·시스템 | 헤더·사이드바·본문·코드·팝오버·모달·폼·스크롤바까지 전환 |
| 화면 밀도 | 간격과 행 높이를 조정하되 터치 표적·가독성의 최소값을 지킴 |
| 고대비 | 배경·글자·경계·포커스를 함께 조정. 색상만으로 상태를 전달하지 않음 |
| 모션 축소 | 반복 장식과 자동 이동을 없애고 필요한 상태 변화를 정적으로 표현 |
| 기본값 복원 | 외관 설정만 초기화. 학습 기록·메모·콘텐츠 초안은 보존 |
| 저장·복원 | `archdeck:appearance:v1:<serviceId>:<userId>`에 저장, 유효값 검사·마이그레이션·탭 간 storage 이벤트 처리. 로그인 전 화면에는 계정과 분리된 기본 테마 사용 |

테마는 `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-accent`, `--color-focus`, 의미색 등 공통 값으로 관리한다. 기존 고정 HEX·`text-white`·암전 배경을 화면별로 전환하고 Tailwind가 공통 값을 참조하게 한다. 처음 페인트 전에 저장된 모드를 적용하여 색상 깜빡임을 줄인다. 저장소를 사용할 수 없으면 현재 세션에서 계속 작동하고 저장되지 않음을 알려 준다.

## 콘텐츠 스튜디오와 개인 기록

콘텐츠 스튜디오는 ADMIN이 사용하는 도구이며 작은 모달 하나에 모든 필드를 넣는 방식에서 구조 편집·미리보기가 가능한 화면으로 전환한다. 토픽·비교·용어·체크리스트 유형을 선택하고 공통 메타데이터와 유형별 필드를 입력한다. 흐름·코드·관련 항목은 직접 작성하며 임의의 샘플 값을 실제 지식처럼 저장하지 않는다.

초안 저장 → 구조·참조·근거 검증 → 읽기 화면과 동일한 미리보기 → 서버 저장 또는 JSON 내보내기의 순서를 제공한다. 필수값·중복 slug·참조 대상·빈 단계·코드 언어·URL 형식을 검증하고 오류 위치로 이동할 수 있어야 한다. 서버 저장 실패 시 성공 문구를 표시하지 않고 초안을 보존한다. 사용자가 직접 작성한 내용은 브라우저 저장인지 서버 저장인지 구분한다.

개인 기록은 서비스 식별자와 변경되지 않는 로그인 계정 ID로 이름 공간을 나누고 다음 단위로 분리한다. 로그아웃·계정 변경 시 메모·초안·학습 상태를 메모리에서 즉시 내리고 새 계정의 데이터만 읽는다. 서버의 사용자 계정·세션과 브라우저의 학습 기록을 같은 저장 문서로 취급하지 않는다. MVP에서는 다른 기기나 브라우저로 자동 동기화하지 않는다. 이 식별자는 저장 분류에만 사용하며 인증 증명으로 사용하지 않는다.

| 데이터 | 저장 단위 | 비고 |
|---|---|---|
| 북마크 | 콘텐츠 유형 + ID | 토픽 외 비교·용어도 같은 모델로 확장 가능 |
| 학습 상태 | 토픽·경로 ID | 미시작·학습 중·이해 완료, 마지막 단계·열람 시각 |
| 메모 | 콘텐츠 유형 + ID | 개인 학습과 적용 아이디어 |
| 체크리스트 수행 | 로컬 수행 ID + 항목 ID | 학습 완료와 구분한 검증 결과·확인 일시·메모 |
| 최근 열람 | 콘텐츠 유형 + ID + 시각 | 보존 개수를 제한하고 지우기 제공 |
| 작성 초안 | 초안 ID + 콘텐츠 유형 | 서버 저장 실패·페이지 이탈에도 복구 |
| 외관 | 별도 설정 문서 | 개인 기록 초기화와 독립 |

단순한 설정·북마크는 localStorage, 크기가 커질 수 있는 초안·메모·콘텐츠 캐시는 IndexedDB로 분리할 수 있게 저장 어댑터를 둔다. MVP 구현에서 저장 크기와 복원 동작을 확인하고 최소한의 저장 수단부터 사용한다. JSON 백업에는 스키마 버전·생성일과 선택한 데이터 범위를 포함하고, 가져오기는 미리보기·검증 후 병합 또는 교체를 선택하게 한다. 개인 기록을 원격 콘텐츠로 덮어쓰지 않는다.

브라우저 기록의 계정별 구분은 다른 계정의 기록이 화면에 섞이지 않게 하는 정책이며 로컬 저장소를 암호화하는 기능은 아니다. 사내 공용 PC에서는 ‘이 브라우저의 내 기록 지우기’를 제공하고, 다른 계정의 백업을 자동으로 가져오지 않는다. 기본 백업에는 비밀번호·세션·계정 관리 정보가 포함되지 않는다.

기존 비계정 저장 키와 공용 `default_user`의 기록은 새 계정에 자동으로 합치지 않는다. 이관 전에 백업하고, 소유자가 검토한 데이터만 로그인한 계정의 브라우저 기록으로 가져온다. 콘텐츠 이관과 개인 기록 이관을 별도로 수행한다.

## 구현 순서와 후속 범위

1. 빈 흐름 렌더링과 학습 기록 경합을 우선 수정하고 데이터 계약을 안정화한다.
2. 공통 콘텐츠 ID·slug·참조와 API 응답을 정리한다. 단순 로그인·계정·서버 역할 검사를 구축하고 개인 기록 저장을 계정별로 분리한다.
3. 라우터·공통 화면 틀·테마·설정 저장을 구축한다. DWP 스타일 헤더·메뉴 배치와 외관 설정을 이 단계에서 완성한다.
4. 토픽 목록·상세·비교·용어·체크리스트를 공통 화면 틀에 연결하고 검색 딥링크·문맥 이동을 완성한다.
5. 홈의 이어 학습·추천 경로와 내 서재, 콘텐츠 스튜디오의 구조 편집·미리보기·JSON 입출력을 연결한다.
6. 사내 공유·로그인·역할 검사와 반응형·접근성·부분 API 실패·데이터 복원 시나리오를 검증한다.

별도 경로 그래프 편집, 퀴즈, 협업 토론, 알림, AI 콘텐츠 생성, Git·문서 웹훅, 개인 기록의 서버 동기화는 초기 출시의 필수 완료 조건으로 두지 않는다. 로그인은 단순 사내 계정과 ADMIN·READER 역할로 범위를 제한하고 SSO·Keycloak 앱 연동과 별도 프로필 제품은 후속 요구가 있을 때 검토한다.
